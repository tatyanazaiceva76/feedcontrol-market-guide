YML · автообновление

Товар пропал после обновления YML? Сначала определите роль файла

У Маркета разные правила для файла, который добавляет товары в каталог, и файла, который передаёт условия продажи. Если перепутать их, можно чинить не ту причину.

Это разные сценарии из официальной справки. Для конкретного магазина учитывайте свои настройки обновляемых полей и модель работы.

Если это файл каталога

  • Проверьте, не перепутали ли файл добавления товаров с файлом условий размещения.
  • Сверьте артикул и статус уже созданной карточки в кабинете.
  • Посмотрите, какие характеристики выбраны для обновления через YML: файл может передавать только часть данных.
  • Помните, что пустое значение поля может изменить прежнее значение; отсутствие товара в файле и пустое поле — разные ситуации.

Удаление товара из каталога выполняется в кабинете, а не исключением оффера из файла добавления.

Если это файл условий размещения

Сначала сохраните предыдущую рабочую версию. Не отправляйте укороченный файл наугад: по правилам Маркета все продаваемые товары должны присутствовать в файле условий размещения.
  1. Сравните количество и список артикулов с прошлой успешной версией. Найдите отсутствующие позиции.
  2. Для затронутого товара проверьте заполненность передаваемых условий продажи и настройку «Скрыть с витрины».
  3. Проверьте атрибут date: без него данные об остатках не обновляются.
  4. Загрузите неархивированный файл для технической проверки в кабинете; исправьте возвращённые ошибки до повторного обновления.

После исправления нужно проверить статус предложения на витрине. Возврат строки в файл сам по себе не гарантирует мгновенного показа.

Что может показать предварительный отчёт

Локальная проверка помогает увидеть проблемы в данных до загрузки. Синтетический образец показывает повтор артикула, нулевую цену и пропуски. Он не устанавливает, какой файл подключён в вашем кабинете и почему реальный товар не показывается.
